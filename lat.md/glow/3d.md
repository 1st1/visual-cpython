# Interactive 3D authoring

The [3D shell](../../glow/iso-glow/assets/gallery-3d.html) supplies real Three.js geometry, orbiting, an orthographic isometric view, and a revolve toggle. It is the source package's mode for the requested interactive 3D medium.

Its built-in examples include a logic board, server rack, and system stack, alongside interactive devices. The shell provides renderer, lines, lighting helpers, palette and theme controls, per-figure buttons, readout, and sound. The original [skill](../../glow/iso-glow/SKILL.md) contains the starter and assembly recipe; general conventions live in [[lat.md/glow/guidance#Glow visualization guidance]].

## Figure lifecycle

Custom figures register an identifier, name, and module in the shell's `FIGS3D` array. Each module owns a scene group, interaction handlers, updates, and presentation metadata.

The module contract is `{ group, key(e), click(hit, event), tick(now, dt), stop(), readout(), demo(), panel, view, info, hint }`. Keyboard handlers report whether they handled input. The button panel contains `[label, key, action]` entries; the view specifies a target and distance. Update the shared readout only when that figure is active. Keep inactive groups hidden and use the stop hook to end activity when leaving a figure.

Avoid identifiers reserved by the built-ins: `tw`, `dr`, `cs`, `tm`, `vm`, `pc`, `lp`, `lg`, `rk`, `sk`, `tt`, and `pl`. Attach a hit identifier to interactive groups and walk up from a raycast mesh to find its owning control. Hold-to-act controls start on pointerdown.

## Geometry and line hierarchy

Authoring coordinates use x and y on the ground plane and z upward. The shell converts these into Three.js coordinates, with 100 authoring units equal to one scene unit.

The larger-y surface is the front face. The shell's coordinate conversion maps authoring z to Three.js y. Rounded boxes, base plates, recesses, planar labels, and canvas screens cover common construction needs. Other Three.js meshes need registration with the outline and crease systems. Record the mesh-list starting position before constructing a figure, then extract its creases once afterward.

Silhouettes are strongest, major folds intermediate, and detail lines dimmest; all normally remain one CSS pixel across zoom levels. The upstream skill discourages a line-weight control. Rounded-plan boxes have sharp rims; surface detail belongs on the matching top, front, or side plane.

## Active parts and information flow

The shell has helpers for pressed controls, LEDs, lit screens, active wires, and moving light points. These can make state transitions and transfer between components visible.

Pressable groups sink and flash; front-facing controls use the shell's front-button press axis. Tick the flash updater during animation. Persistent activation uses a latched material state. Screens use their own canvas and must redraw on theme or accent changes through the shell's theme hooks.

Wire animation helpers construct curves, accumulate segment lengths, sample positions by distance, and move a glow sprite along the result. Distance-based sampling avoids unequal speeds on unevenly spaced curve samples. Couple transfer progress and endpoint changes to the figure state, with pointer, keyboard, and demo actions sharing the same transitions.

The hairline 3D rules reserve physical illumination for real sources such as bulbs, LEDs, and screens; they reject arbitrary light cones and glowing fans or exhausts. Signal pulses are an explicit information-flow convention. Glow sprites and haze disappear in light mode, so active lines, surfaces, and readouts must remain sufficient to communicate state.

## Imported models

The source skill supports restyling GLB models as dark solids with silhouette and crease lines. Imported geometry still needs meaningful interactive state.

Its local-file recipe embeds a GLB as base64 and parses the bytes, avoiding a fetch from a file URL. It bakes mesh transforms, centers and scales geometry, recomputes normals, and replaces materials. This recipe is a restyling path, not a promise to preserve original materials or animation.

Clean duplicate coincident faces, check handedness, split moving parts, set pivots from geometry, and remove problematic transparent panels where open frames suffice. Attribute CC-BY models with author, license, and the fact that they were restyled.

## Physical anatomy reference

The [anatomy guidance](../../glow/iso-glow/references/anatomy-builds.md) applies to real objects with exploded assemblies or section cuts. Its physical dimensions and disassembly rules do not directly describe software internals.

For a physical model, research dimensions, parts, and teardown order from primary references before modeling. Use realistic silhouettes and complete joint outlines, with restrained stepped shading and texture. Explode each assembly independently in real disassembly order and direction, keep parts visible, and ease the camera to fit. Exploding and section cutting are independent controls.

Exploded labels use short titles, sourced values, and leaders; use nonoverlapping columns on desktop and pins with a scrollable legend on phones. Section cuts start off, persist their toggle, and need capped or clipped geometry with a heavier cut outline. Custom shaders need clipping support, and shader include directives must start on their own lines.

The transferable presentation lessons are unobscured components, camera framing that follows the displayed state, labels that avoid overlap, and usable mobile controls. The upstream mobile layout uses a bottom toolbar with 38-pixel tap targets and a readout above it. Physical flow simulations should be computed from relevant data; distinguish sourced facts from approximations when presenting any model.
